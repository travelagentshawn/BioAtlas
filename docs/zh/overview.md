# 项目概览

> **在线初稿：** [打开 BioAtlas 网页](https://bioatlas-draft-git-feat-field-modules-v1-7rk82my46w-2808.vercel.app)。这是独立的公开阅读部署，不代表 PR 已合并或所有科学记录已审核。

BioAtlas 是一个开源的**旅途动植物图鉴**：把分子系统发育（谁和谁亲缘更近、何时分开）与传统分类学（界门纲目科属种）放进同一套结构化数据，让旅行者认出路上遇到的银杏、白鹭、梅花鹿，并知道它们在生命之树上的位置。

## 主界面的两种入口

主界面采用并列的双入口，而不是把两种信息强行混成一张图：

- **自然图鉴（可用工作界面）**：作为默认首页，承载物种检索、今日/当季观察、旅行场景、自然地图、物候、野外辨认、保护信息、声音、学习与行程清单等实际使用功能。
- **进化树（系统发育界面）**：独立展示 BioAtlas 自有主树，支持展开/折叠、分类大纲、分歧年代与物种/分类单元详情跳转。

两者共享同一套 API 与物种/分类单元 ID。进化树是科学关系的专门视图；自然图鉴是日常检索和观察的工作界面。两者互为主入口，不互相替代。外部分类权威仅作为来源级对照，不会自动改写 BioAtlas 自有主树。

## 它是什么

- **一份公开的结构化数据**：`data/` 下的 JSON 文件，经 `schema/` 校验，任何人和任何 AI 都能读、改、扩展。
- **一个静态 JSON API**：由 `tools/` 编译成 `dist/api/v1/`，是数据与界面之间**唯一**的接口（见 [API 契约 v1](api-contract.md)）。
- **一个零依赖的网页界面**：`ui/` 只通过 API 取数。
- **一份在线说明书**：就是你正在看的页面，源文件在 `docs/`。
- **一个行程工作台**：连接图鉴与旅行规划（见[对接旅行工作台](workbench-integration.md)）。

## 设计原则

1. **科学严谨优先于内容数量。** 分歧年代永远是区间并带来源；并系类群被明确标注；每条记录有审核状态。
2. **解耦。** 数据、界面、文档可由不同的人或不同的 AI 分别开发与编译，只通过契约协作。
3. **模型中立。** 任何 AI 或人都可以参与；约定写在仓库里，而不是某个模型的记忆里（见[多 AI 协作协议](ai-collaboration.md)）。
4. **可延展。** 新增物种只需新增一个 JSON 文件；新增模块只需新增契约端点。

## 目前的状态（务必阅读）

> 当前 `data/` 中的全部记录都是 **`seed`（初稿）**：由 AI 起草，尚未逐条对照原始文献核对。引用的 DOI、分歧年代区间、IUCN 等级都需要人工核对后才能升级为 `reviewed`。界面上每个页面都会显示这一状态。

这不是缺陷，而是流程：先有可协作的骨架，再由人和 AI 逐条核对、提升审核等级。

## 仓库地图

| 路径 | 内容 | 谁负责 |
| --- | --- | --- |
| `data/` | 分类单元、物种、场景、文献 | 数据方 |
| `schema/` | 记录的 JSON Schema | 数据方 |
| `contract/` | API v1 响应形状与端点清单 | 双方共同维护，改动需谨慎 |
| `tools/` | 校验、编译、本地服务、测试 | 数据方 / 工具 |
| `ui/` | 网页界面 | 界面方 |
| `docs/` | 本说明书 | 任何人 |
| `AGENTS.md`、`llms.txt` | 给 AI 的入口 | 任何人 |
